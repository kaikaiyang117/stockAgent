# 股价异动解释 Agent：需求分析

## 1. 项目目标

构建一个可在浏览器中运行的、完全自包含的“股价异动解释 Agent”演示应用。应用以模拟的交易行情、交易日历、公告、新闻、行业事件和财务数据为输入，将事件统一映射到交易日，并通过收盘价/K 线视图、事件时间线和浮动 Agent 助手解释指定异动日的可能影响因素。

系统目标是帮助用户区分“发生了什么”和“可能如何相关”，不对股价做预测或投资推荐，也不把时间上的同时发生表达为已证实因果。

## 2. 功能需求

### 2.1 行情与异动

- 展示一段确定性的模拟交易行情，至少包含日期、开盘价、最高价、最低价、收盘价、成交量和涨跌幅。
- 支持收盘价折线或 K 线图；图表可选择交易日。
- 识别或预先标记至少一个明显上涨或下跌的交易日，并在图表中突出显示。
- 选中交易日后，页面显示该日的行情摘要、涨跌信息和对应事件。

### 2.2 事件时间线

- 展示公告、新闻、行业事件、财务数据等模拟事件。
- 事件统一转换到交易所时区（Asia/Shanghai），并依据交易日历映射到交易日：
  - 开盘前事件映射到当日。
  - 交易时段事件映射到当日。
  - 收盘后事件映射到下一交易日。
  - 非交易日事件映射到下一交易日。
- 交易日与事件时间线联动：选择交易日后自动筛选并高亮相关事件。
- 点击事件后展示标题、发布时间、转换后的交易所时间、类型、来源、摘要、分类和证据。
- 对范围外事件、无相关事件和异常数据给出明确状态提示。

### 2.3 证据与解释分类

- 事件或解释必须明确标注为：事实、观点、时间相关性或因果假设。
- 因果假设必须同时展示依据、置信度和不确定性提示。
- 证据不足时必须明确显示“证据不足”，不能将假设写成事实。

### 2.4 浮动 Agent 助手

- 根据当前选中的异动日返回 1～3 个可能影响因素。
- 每个因素关联至少一个具体事件，并支持点击因素定位到对应事件。
- 每个因素展示摘要、分类、依据；因果假设额外展示置信度和不确定性。
- Agent 使用确定性规则/预设结果模拟，不接入真实大模型。

### 2.5 状态与可用性

- 提供 Loading、空数据、时间范围外事件、异常数据、没有相关事件、证据不足等状态提示。
- 桌面端优先，同时保证窄屏下主要内容可读和可操作。
- 颜色、标签和文字共同表达分类，不只依赖颜色传达信息。

## 3. 非功能需求

- 所有运行数据内置在项目中，运行结果确定、可复现，不依赖网络或真实金融数据。
- 核心时间映射、异动判定和 Agent 解释逻辑应与 UI 解耦，并可被单元测试直接调用。
- 使用严格的 TypeScript 类型定义，避免无必要的 `any`。
- 项目可通过标准 npm 命令启动、构建和测试。
- 代码结构清晰，文档说明数据模型、时间映射规则、交互流程和已知限制。
- 至少提供 3 个自动化测试，覆盖盘后事件映射、非交易日事件映射、证据不足的因果假设。

## 4. 不做的内容

- 不接入真实证券行情 API、新闻 API 或联网采集内容。
- 不使用真实股票数据，不实现价格预测、股票推荐或交易功能。
- 不实现复杂技术指标、服务端数据库、服务端持久化或用户系统。
- 不实现真实 LLM、RAG 或多轮聊天。
